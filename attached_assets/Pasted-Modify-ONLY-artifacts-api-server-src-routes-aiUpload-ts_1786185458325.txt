Modify ONLY:

artifacts/api-server/src/routes/aiUpload.ts

Goal:
Separate metadata/control-total extraction from transaction extraction.

Do NOT redesign the rest of the PDF pipeline.
Do NOT change transaction validation, running balance validation, retry logic, correction logic, deduplication, frontend, AI chat, Money actions, auth, or import confirmation.

==================================================
WHY THIS CHANGE IS NEEDED
==================================================

Current buildPagePrompt() asks a single Vision call per page to do all of this at once:

1. identify page type
2. detect table schema
3. extract every transaction
4. extract metadata
5. extract opening/closing balances
6. extract statement-period summary totals

Real production testing now shows:
- transaction rows are being extracted
- but metadata/control totals are all null:
  summaryIncome = null
  summaryExpenses = null
  openingBalance = null
  closingBalance = null

This causes:
hasVerification = false
extractionComplete = false
importAllowed = false

The likely issue is that the large transaction JSON response crowds out or destabilizes the metadata fields.

We want two independent extraction tracks.

==================================================
1. KEEP TRANSACTION EXTRACTION SEPARATE
==================================================

Keep buildPagePrompt() focused on:

- pageType
- tableSchema
- transactions

Remove metadata extraction responsibility from this prompt.

It should NOT return:
- bank
- accountNumber
- period
- openingBalance
- closingBalance
- summaryIncome
- summaryExpenses

Do NOT otherwise change the transaction instructions.

Do NOT alter:
- debit/credit rules
- balance column logic
- multi-line description handling
- row skip rules
- transaction JSON shape

==================================================
2. ADD A DEDICATED METADATA PROMPT
==================================================

Add a new function:

buildMetadataPrompt(pageNum: number, totalPages: number): string

This prompt must extract ONLY document metadata and statement-level control values.

It must return JSON equivalent to:

{
  "bank": "bank name" | null,
  "accountNumber": "IBAN/account number" | null,

    "from": "YYYY-MM-DD",

    "found": false
  },

  "closingBalance": {
    "found": true,

  } | {
    "found": false
  },

  "summaryIncome": {

    "found": false

}

==================================================
3. METADATA PROMPT RULES
==================================================

The metadata prompt must explicitly state:

- Do NOT extract transactions.
- Do NOT return transaction rows.
- Do NOT calculate totals from transaction rows.
- Copy only values visibly printed as document-level metadata/control values.
- sourceLabel must be the exact text printed next to the value.

Opening balance examples may include:
- Opening balance
- Algsaldo
- Avamissaldo
- Algjääk
- Starting balance

Closing balance examples may include:
- Closing balance
- Lõppsaldo
- Sulgemissaldo
- Lõppjääk
- Ending balance

Income summary examples may include:
- Total credits
- Total income
- Sissetulekud
- Laekumised
- Krediteeriti kokku

Expense summary examples may include:
- Total debits
- Total expenses
- Väljaminekud
- Maksed
- Debiteeriti kokku

IMPORTANT:
These are semantic examples only.
Do NOT hard-code any bank-specific amount or any user-specific value.

Reject:
- individual transaction amounts
- running balance values
- per-page subtotals
- "Page total"
- "Lehe kokku"
- transaction-row "Jääk"/"Balance"
- account opening/closing values as income/expense totals
- income/expense totals as opening/closing balances

If the field is not clearly visible on that page:
return { "found": false }

Do NOT guess.

Inside extractBankStatementOCR():

pageResponses

Use buildPagePrompt() on every page for:

Track B:

For example conceptually:

const [pageResponses, metadataResponses] = await Promise.all([
  Promise.all(...transaction/page calls...),
  Promise.all(...metadata calls...)
])

Do not serialize them unnecessarily.
