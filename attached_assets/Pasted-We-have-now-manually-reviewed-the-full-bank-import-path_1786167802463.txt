==================================================
A. aiUpload.ts — FIX RECOVERY LOGIC
==================================================

CONFIRMED BUG:

The current code uses:

const incomeDiff1 =
  summaryIncome != null ? Math.abs(totalIncome - summaryIncome) : 0

const expenseDiff1 =
  summaryExpenses != null ? Math.abs(totalExpenses - summaryExpenses) : 0

Then it treats every positive absolute difference as “missing” data and runs a second pass that only ADDS transactions.

This is wrong.

Example:

expected income = 1000
extracted income = 1500

Math.abs(...) = 500

The current retry prompt tells the model approximately 500 EUR is missing, even though 500 EUR is actually OVER-EXTRACTED.

The second pass can therefore make an already-wrong extraction even worse.

REQUIRED FIX:

Use SIGNED deltas:

const incomeDelta =
  summaryIncome != null ? summaryIncome - totalIncome : 0

const expenseDelta =
  summaryExpenses != null ? summaryExpenses - totalExpenses : 0

Meaning:

delta > 0
→ extracted total is too low
→ something may be missing

delta < 0
→ extracted total is too high
→ something may be duplicated, misread, or misclassified

Do NOT call the current “find missing rows” second pass when the extracted total is already too high.

B. aiUpload.ts — REPLACE ADD-ONLY RECOVERY
==================================================

The current retry pipeline can only append transactions:

transactions.push(t)

This is unsafe.

Replace the retry result shape with a correction-oriented result.

Equivalent structure:

{
  "added": [...],
  "corrected": [...],
  "removed": [...],
  "uncertain": [...]
}

The retry pass must be used only when validation says recovery is actually needed.

Rules:

1. If totals are too LOW:
   - search for genuinely omitted rows
   - allow "added"

2. If totals are too HIGH:
   - do NOT search for more transactions
   - inspect likely duplicate/misread/misclassified rows
   - allow "corrected", "removed", or "uncertain"

3. Application code decides whether a correction is accepted.

4. Never blindly append everything returned by the second pass.

5. If a correction cannot be proven:
   mark the row needsReview and block import.
